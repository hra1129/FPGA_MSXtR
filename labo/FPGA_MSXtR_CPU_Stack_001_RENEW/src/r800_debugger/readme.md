# BIOS CPU Switch Debugger

Z80またはR800のコアが0180hをM1フェッチした時点から、1回分のCPU切替を受動記録する。128bit x 128wordの同期RAMを使用する。入口ではPC・SP・AF・HLと、直前2回のメモリ書込みから再構成したCALL戻り先を保存する。SP/SP+1に対応する書込みを観測できなかった場合、そのbyteの有効フラグは0となり、PicoではRET=UNKNOWNと表示する。追加のメモリ読出しは発行しない。

記録対象はCPUのメモリ/I/O読書き、CPU切替、04BBh・04BFh・04D1hのM1フェッチ時のスナップショット、RET後のPC。メモリアドレスは論理アドレス。I/OイベントにはA8hとFCh-FFhなどのslot/mapper操作が含まれ、メモリページ切替の追跡に使える。読出し応答は要求時のアドレス・I/O区分・CPU・PC・レジスタと対応付ける。バスイベントとCPU切替が同時の場合、バスイベントを先に記録してCPU切替を次に記録する。ENTRY/SNAPのPCはフェッチアドレス、それ以外はコアの公開PCであり、オペランド取得による進行も含む。

04D1hのRETを経てPCが04D1h/04D2h以外へ移ったらRETURNを保存して停止する。128件に達した場合も停止する。MSXリセットまたは再アームで状態と件数をクリアする。通常起動中も0180hが呼ばれるため、対象の操作直前に再アームする。

## SPI

- 13h: 件数を下位・上位の2byteで返し、古い順に16byteレコードを送信する。件数はコマンド受付時の値に固定する。0件なら件数2byteだけで終了する。
- 各応答byteの前にspi_intrを待つ。速度は70MHzのままで、Pico側の1usのbyte間待ちも維持する。
- 読出しは非破壊。途中でCSを解除しても記録は残り、次の13hでは先頭から再読出しする。
- 14h: 再アーム。記録をクリアして0180hトリガを待ち直し、処理後にspi_intrで通知する。応答データはない。
- どちらのコマンドもCPUメモリバスへの要求は出さない。

各レコードはlittle-endian。

| Byte | 内容 |
| --- | --- |
| 0 | bit7: CPU (0=Z80, 1=R800)、bit4: I/Oサイクル (1=I/O, 0=memory)、bit3:0: イベント (1=ENTRY, 2=SNAP, 3=READ, 4=WRITE, 5=OWNER, 6=RETURN) |
| 1 | READ/WRITE: データ、ENTRY: 戻り先下位/上位byteの有効フラグ(bit0/bit1)、その他: 0 |
| 2-3 | READ/WRITE: I/O portまたはmemory address、ENTRY: 再構成した戻り先、その他: 観測時のバスアドレス |
| 4-5 | PC |
| 6-7 | SP |
| 8-9 | AF |
| 10-11 | HL |
| 12-15 | 再アーム後のclk42mカウント(32bit、42.95454MHz) |

## Pico操作

Picoがバスを持つとき、0キーで14h再アーム、9キーで13hを読み出して標準出力へ表示する。MENUでPicoへ移し、0キー、MENUでCPUへ戻し、CPU切替を実行した後、MENUでPicoへ移して9キーを押す。

今回の調査では、再アーム後にBASICでDEFUSR=&H180:A=USR(0)を1回実行し、9キーで一覧を取得する。ENTRYのRET/SPと、FFFDh/FFFEhのWRITE/READ、04BBh/04BFh/04D1hのSNAP、RETのスタックREAD、末尾RETURNのPC/SPを比較する。正常OpenMSXでは今回のBASIC操作のENTRY/RETURNはSP=E2BBh、戻り先3297hだったが、実機のBASIC状態により値は変わり得る。

末尾がRETURNなら戻りまで記録完了。RETURNがなく128件なら容量打切り、128件未満なら途中記録または読出しタイムアウトによる部分結果。タイムアウトは別途メッセージ表示する。2回目のUSRを調べる際も再アームし、1回目の記録と分ける。
