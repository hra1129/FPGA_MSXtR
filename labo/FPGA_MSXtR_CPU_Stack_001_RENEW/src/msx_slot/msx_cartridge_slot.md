# MSXカートリッジスロット タイミングチャート資料

出典: テクハンwiki「Appendix A.7 カートリッジ ハードウェア仕様」
https://ngs.no.coocan.jp/doc/wiki.cgi/TechHan?page=Appendix+A%2E7+%A5%AB%A1%BC%A5%C8%A5%EA%A5%C3%A5%B8+%A5%CF%A1%BC%A5%C9%A5%A6%A5%A7%A5%A2%BB%C5%CD%CD

「●スロットのタイミングチャート」に掲載されている6種類の図(M1サイクル基本/拡張スロット、
メモリサイクル基本/拡張スロット、I/Oサイクル基本/拡張スロット)のうち、`msx_slot.v` の
基本スロット実装(TangNano20K内蔵FPGA側のCPUスロット制御)に関係する「基本スロット」3図から
読み取った実測値をまとめる。単位はすべて ns。「T1+145」は「T1の先頭(CPUクロック立ち上がり)
から145ns後」を意味する。

## 前提: ff_slot_timing とチャートの対応

- `msx_slot.v` の `ff_slot_timing`(clk_215m = 214.7727MHz でカウント)は、CPUクロック
  (3.579545MHz、周期 約279.365ns)1周期の間に 0〜59 をカウントするカウンタ。
- チャート上の縦線(CPUクロックの立ち上がり/立下りの基準線)は `ff_slot_timing` の
  `0`(立ち上がり)と `29`(立下り)に対応する。
- `ff_t_state`(c_t1, c_t2, c_t3, c_t4, c_t5)の各ステートはチャートの T1, T2, TW, T3, T4
  に対応するCPUクロック1周期分であり、ステートが変わるたびに `ff_slot_timing` は 0 に
  リセットされる。
- clk_215m の周期は 1000/214.7727 ≈ 4.656ns。
- レジスタは非ブロッキング代入のため、「`ff_slot_timing == X` を条件にする」と、信号の値が
  実際に変化して見えるのは次のクロック、すなわち `X+1` の位置になる。そのため、チャート上で
  遅延Nns(クロック数 D = round(N/4.656))後に変化させたい場合、RTLの比較定数は
  `(基準位置) + D - 1` とする。
  - 例: slot_clock_n はCPUクロックから40ns遅延(D=8clock)させたいので、
    条件値は `0+8-1=7`(立ち上がり)、`29+8-1=36`(立下り)となる。

## M1サイクル 基本スロット(T1, T2, TW, T3, T4)

Z80のオペコードフェッチサイクル。必ず `/MREQ = L`, `/RD = L` になり、`/WR` は発生しない。

| 信号 | アサート | リリース |
|---|---|---|
| MREQ | T1+145 | T3+145 |
| SLTSL | T1+155 | T3+155 |
| CS(CS1/CS2) | T1+195 | T3+185 |
| M1 | T1+160 (解除) | T3+160 (再アサート) |
| RD | T2+155 | T3+145 |
| RFSH | T3+190 | T4+180 |
| A0〜A15 | T1+170 (アドレス確定) | - |
| WAIT | (入力信号、TWでmin95) | - |

- M1サイクルはTW(ウェイト)を1ステート挟むため、RDのアサートはT2まで遅れる。

## メモリサイクル 基本スロット(T1, T2, T3、ウェイトなし)

M1以外の通常メモリアクセス(`/M1 = H`)。読み出し(RD)と書き込み(WR)の波形は
点線で3つの区画に分かれて記載されている: ①MREQ/SLTSL/CS/WAIT(RD・WR共通)、②WR側、③RD側。

| 信号 | アサート | リリース |
|---|---|---|
| MREQ | T1+145 | T3+145 |
| SLTSL | T1+155 | T3+155 |
| CS(CS1/CS2) | T1+195 | T3+185 |
| WAIT | (入力信号、min95) | - |
| WR | T2+140 | T3+120 |
| D0〜D7(write) | T1+210 (データ確定目安) | - |
| RD | T1+155 | T3+145 |
| D0〜D7(read) | (min80/min0、CPU側セットアップ・ホールド規定) | - |

- MREQ/SLTSL/CSの値はM1サイクルと同じ。
- ウェイトが無いため、RDはT1のうちにアサートされる(M1サイクルのT2アサートより早い)。
- WRはCPUが書き込みデータを出力してからアサートする必要があるため、T2まで遅れる。

## I/Oサイクル 基本スロット(T1, T2, TW, T3、ウェイトあり)

I/Oポートアクセス。Z80仕様によりI/Oサイクルにも自動的にウェイトが1ステート入る
(MREQの代わりにIOREQが使われる点以外はメモリサイクルと同様の区画分け)。

| 信号 | アサート | リリース |
|---|---|---|
| IOREQ | T2+135 | T3+145 |
| A0〜A15 | T1+170 (アドレス確定) | - |
| WAIT | (入力信号、min95) | - |
| WR | T2+125 | T3+120 |
| RD | T2+145 | T3+145 |

- I/OサイクルもTWを挟むため、IOREQ/WR/RDのアサートはいずれもT2まで遅れる。

## msx_slot.v への反映状況

- `slot_clock_n`: CPUクロックから40ns遅延という考え方で `c_sig_clock_rise=7`,
  `c_sig_clock_fall=36` を使用(2026/8/31時点で反映済み)。
- `slot_merq_n`(MREQ): メモリ/M1サイクルとも T1+145 / T3+145 で一致するため、
  `c_sig_merq_assert=30`, `c_sig_merq_release=30` を使用(反映済み)。
- `slot_rd_n`(RD): メモリサイクルの T1+155 / T3+145 を基準に
  `c_sig_rd_assert=32`, `c_sig_rd_release=30` を使用(反映済み)。
  M1サイクルはT2アサートだが、`ff_t_state==c_t1` の判定と数値の組み合わせで
  近似的に同じタイミングとして扱っている(M1固有のウェイト挿入との厳密な整合は未対応)。
- `slot_wr_n`(WR): `/WR` は `/M1 = H` の時のみ発生するため、メモリ/I/Oサイクルの
  値を採用。アサートはメモリ(140ns)とI/O(125ns)の遅い方＝メモリの値を採用し、
  リリースは両サイクルで一致する120nsを採用。
  `c_sig_wr_assert=29`(`ff_t_state==c_t2` で判定するよう変更済み)、
  `c_sig_wr_release=25`(`ff_t_state==c_t3`)。
- `slot_iorq_n`(IORQ)、`slot_sltsl*_n`、`slot_cs*_n`、`slot_m1_n`、`slot_rfsh_n` は
  本資料作成時点では未調整(既存の `c_sig_select`/`c_sig_strobe`/`c_sig_release`/
  `c_sig_m1_release`/`c_sig_rfsh_assert`/`c_sig_rfsh_release` を使用したまま)。
  特にIORQはチャート上T2アサートだが、現状の実装は `ff_t_state==c_t1` を使っており
  WR修正前の状態と同様の未整合が残っている。
